Рабочее название: **Fretlines** (можно поменять).

Документ состоит из трёх частей:
1. Техническое задание (что строим и зачем).
2. UI/UX и дизайн-система (как это выглядит и ощущается).
3. Готовый промпт для Claude Code — копируешь целиком и вставляешь.

> **Изменения после этапа 0 (7 ноября 2026), по решению автора.** Где ниже написано иначе,
> действует этот список.
> - **Без Docker.** Приложение запускается в Windows двойным кликом по `start.bat`. Python 3.11,
>   библиотеки и модели ставятся в папку проекта (`.tools/`, `.models/`). Вместо Redis и RQ —
>   очередь внутри API: каждый разбор идёт в отдельном процессе, прогресс пишется в SQLite.
>   Видеокарта NVIDIA включается через `gpu.bat`.
> - **Ссылки с YouTube и TikTok разрешены** (yt-dlp) — для личной практики, в дополнение к

>   JetBrains Mono.
> - **Гитарный звук партий** — синтезатор alphaTab с SoundFont, чтобы сразу услышать, как
>   должно звучать.
> - **Звучать как оригинал** (второй круг правок): плеер играет саму запись в такт табам
>   (режимы «Запись», «Вместе», «Партии», любую дорожку можно заглушить). Темп в табах
>   повторяет запись по тактам. Добавлена партия «как в записи» (ноты гитары из оригинала,
>   Basic Pitch), аккорды точнее за счёт хромы по нотам, звук синтезатора — банк MuseScore
>   General вместо маленького встроенного.
> - **Текст песни как в караоке**: lrclib.net + Whisper по вокальной дорожке. Есть караоке-строка,
>   режим «Текст» с аккордами над словами и слова под нотами. В сеть уходят только название и
>   исполнитель; `FRETLINES_LYRICS=local` отключает и это.

# Часть 1. Техническое задание

## 1.1. Цель

Веб-приложение, которое берёт песню (аудиофайл пользователя), разбирает её на составные части и автоматически раскладывает на **гитарные партии для 1–4 игроков**: мелодия вокала, бас, ритм, фон, перкуссия. У каждой партии свой уровень сложности. Результат — табы для каждого игрока, общая партитура и плеер, где можно репетировать свою партию под остальные.

Главный сценарий: три друга с гитарами хотят сыграть любимую песню вместе, и каждый получает партию под свой уровень.

## 1.2. Пользователи

- **Гитарист среднего уровня** (основной): умеет читать табы, хочет сыграть мелодию песни или собрать партии для группы.
- **Новичок**: недавно взял гитару, нужны простые аккорды и бой.
- **Небольшая группа (2–4 человека)**: репетируют вместе, у каждого своя роль.

## 1.3. Основные сценарии

1. **Разбор песни.** Загружаю mp3/wav/m4a → вижу прогресс обработки по этапам → получаю проект песни.
2. **Настройка состава.** Указываю, сколько нас и у кого какая гитара (электро / акустика, строй, каподастр) → распределяю роли.
3. **Сложность.** Для каждого игрока выбираю: упрощённо / средне / полностью.
4. **Тональность и темп.** Транспонирую песню, ставлю каподастр, замедляю для разучивания.
5. **Репетиция.** Включаю общее воспроизведение, глушу/выделяю партии, играю свою под остальные. Курсор бежит по табу.
6. **Экспорт.** Скачиваю табы каждого игрока (PDF, Guitar Pro / alphaTex, MusicXML, MIDI).
7. **Библиотека.** Мои разборы сохраняются, их можно открыть позже.

## 1.4. Функциональные требования

### Загрузка и анализ
- Форматы: mp3, wav, m4a, flac; до 15 минут; до 50 МБ.
- Этапы обработки (каждый виден в UI):
  1. Разделение на стемы: вокал, бас, барабаны, гитара, пианино, остальное (Demucs, модель `htdemucs_6s`).
  2. Темп, доли и такты (beat tracking).
  3. Тональность.
  4. Аккорды по времени (распознавание аккордов на гармонических стемах).
  5. Мелодия вокала: высота голоса (torchcrepe / CREPE или Basic Pitch) → ноты с квантованием по сетке долей, сглаживание вибрато и скольжений.
  6. Басовая линия: транскрипция стема баса (Basic Pitch) → монофоническая линия.
  7. Фон: полифоническая транскрипция стемов гитары/пианино/остального (Basic Pitch) → выделение заметных риффов и проигрышей.
  8. Ритм-рисунок: по барабанам → схема боя/перебора.
- Обработка идёт в фоне (очередь задач). Пользователь видит процент и текущий этап, может закрыть вкладку и вернуться.

### Состав и роли
- 1–4 игрока. У каждого: имя, тип гитары, строй (стандарт E, Drop D, полутон вниз и т. д.), каподастр (0–7).
- Роли: **Мелодия**, **Бас**, **Ритм**, **Фон**, **Перкуссия**.
- Если игроков меньше, чем ролей, система объединяет роли по приоритету (например, для 1 игрока: фингерстайл = мелодия + бас + аккорды; для 2: лид (мелодия + фон) и ритм (аккорды + бас)).
- Пресеты: «Соло фингерстайл», «Дуэт: лид + ритм», «Трио: мелодия + ритм + бас», «Квартет».
- Роли можно переназначать перетаскиванием.

### Движок аранжировки (ключевая часть)
- **Раскладка по грифу**: для каждой ноты выбирается струна и лад через динамическое программирование, которое минимизирует перемещения руки. Ограничения: растяжка ≤ 4 ладов (на «упрощённо» ≤ 3), не больше одной ноты на струну одновременно, учёт строя и каподастра.
- **Диапазон**: если мелодия выходит за удобный диапазон гитары, она сдвигается на октаву целиком или по фразам.
- **Уровни сложности**:
  - *Упрощённо*: открытые аккорды (или упрощение баррэ до мажор/минор), бой из 4–8 долей, мелодия без украшений, до 2 нот на долю, бас по корням аккордов.
  - *Средне*: септаккорды, переходы, простые риффы, ноты до восьмых.
  - *Полностью*: максимально близко к транскрипции, украшения (слайды, бенды, хаммеры, если распознаны).
- **Фингерстайл** (один игрок): мелодия на верхних струнах + бас-нота аккорда на сильные доли + заполнение аккордом, с проверкой играбельности.
- Каждая партия отдельно редактируется вручную: ноту можно сдвинуть, удалить, поменять струну.

### Тональность, темп, строй
- Транспонирование ±12 полутонов, подсказка «лучший каподастр» (минимум баррэ).
- Темп 50–120 % без изменения высоты (time-stretch).
- Смена строя пересчитывает раскладку.

### Отображение и воспроизведение
- Рендер табов и нотного стана через **alphaTab** (мульти-трек: каждая партия — отдельный трек).
- Режимы: «Моя партия» (крупно один трек), «Партитура» (все треки), «Аккорды» (лист аккордов с текстом-тактами).
- Плеер: play/pause, перемотка по тактам, петля A–B, метроном, отсчёт перед стартом, mute/solo для каждой партии, громкость партий.
- Синтезированный звук партий (soundfont гитары/баса), плюс опционально оригинальные стемы под партиями.
- Синхронный курсор по табу.

### Экспорт
- PDF (табы игрока или вся партитура), alphaTex / Guitar Pro (.gp), MusicXML, MIDI.
- Ссылка «поделиться в группе» — приватная, открывается только по ссылке, без публичного каталога.

### Библиотека
- Список моих разборов: обложка (генеративная, без чужих артов), название, исполнитель, тональность, темп, дата.
- Сохранение настроек состава и правок.

## 1.5. Нефункциональные требования
- **Работа локально**: всё запускается на своём компьютере через Docker Compose. С NVIDIA GPU обработка быстрее; без GPU — медленнее, но работает.
- Время обработки 4-минутной песни: цель ≤ 3 мин на GPU, ≤ 12 мин на CPU.
- Интерфейс быстрый: смена сложности/транспонирование пересчитываются за ≤ 1 с (аранжировка на сервере по уже сохранённой транскрипции, без повторного анализа).
- Адаптивность: десктоп — основной, планшет и телефон — просмотр табов и плеер.
- Доступность: контраст текста ≥ 4.5:1, управление плеером с клавиатуры (пробел — play, ←/→ — такт, L — петля).

## 1.6. Ограничения и честные ожидания
- Автотранскрипция — **черновик**. Аккорды и мелодия вокала распознаются хорошо, сложные гитарные соло — приблизительно. Поэтому ручная правка обязательна в функционале.
- **Авторские права**: пользователь загружает свои файлы, разборы приватные. Нет публичного каталога песен и табов, нет скачивания с YouTube/стримингов.

## 1.7. Архитектура
- **Frontend**: React + TypeScript + Vite, Tailwind CSS, Zustand (состояние), alphaTab (табы и плеер), Framer Motion (анимации).
- **Backend**: Python 3.11, FastAPI, очередь задач (RQ или Celery) + Redis, SQLite → PostgreSQL.
- **ML/аудио**: Demucs (`htdemucs_6s`), Basic Pitch, torchcrepe, librosa (темп, доли, тональность, time-stretch), распознавание аккордов (chord-recognition модель или шаблонный метод по хромаграмме).
- **Движок аранжировки**: собственный Python-модуль `arranger/` — внутренний формат нот (время, длительность, высота, роль) → раскладка по грифу → упрощение по уровню → экспорт в alphaTex/MusicXML/MIDI.
- **Хранение**: файлы в локальной папке `storage/` (оригинал, стемы, транскрипции JSON, экспорт).

## 1.8. Этапы

| Версия | Что входит | Результат |
|---|---|---|
| **v1 (MVP)** | Загрузка, стемы, аккорды, мелодия вокала, бас. Три партии: мелодия / ритм / бас. Табы через alphaTab, базовый плеер. | Можно разобрать песню на трио и сыграть |
| **v2** | Уровни сложности, транспонирование, каподастр, строй, темп, петля A–B, экспорт PDF/GP | Удобно учить и подстраивать под себя |
| **v3** | Гибкий состав 1–4, пресеты, фон и перкуссия, фингерстайл, ручной редактор нот, библиотека, приватные ссылки | Полноценная платформа для группы |

## 1.9. Критерии приёмки v1
- Песня 3–5 минут обрабатывается без ошибок, прогресс виден по этапам.
- Аккорды на простой поп/инди-песне совпадают с эталоном ≥ 80 % по времени.
- Мелодия вокала узнаваема при воспроизведении синтезом.
- Все три партии играбельны: нет растяжек > 4 ладов, нет двух нот на одной струне одновременно.
- Табы отображаются, плеер синхронно ведёт курсор, mute/solo работают.
- Тесты движка аранжировки проходят.

# Часть 2. UI/UX и дизайн-система

## 2.1. Настроение

Ночной, кинематографичный, монохромный. Как чёрно-белая плёночная фотография ночного города: глубокий чёрный, мягкий белый, зерно, виньетка, немного дымки. Минимум цвета, много воздуха, крупная выразительная типографика. Ощущение: «я в студии ночью, свет приглушён, играет музыка».

Важно: **это вдохновение эстетикой, а не копия** — никаких логотипов, названий, обложек и фото конкретных групп.

## 2.2. Цвета (токены)

Тёмная тема по умолчанию, светлая — опционально.

| Токен | Тёмная | Светлая | Где |
|---|---|---|---|
| `--bg` | `#0A0A0B` | `#F2F1EE` | фон |
| `--surface` | `#141416` | `#FFFFFF` | карточки, панели |
| `--surface-2` | `#1D1D20` | `#E8E7E3` | вложенные блоки, ховеры |
| `--line` | `#2A2A2E` | `#D2D0CA` | разделители, сетка табов |
| `--text` | `#ECEBE7` | `#111112` | основной текст |
| `--text-dim` | `#8C8B87` | `#5E5D59` | вторичный текст |
| `--accent` | `#F5F3EE` | `#0A0A0B` | активные элементы — «свет» |
| `--glow` | `rgba(255,255,255,0.08)` | `rgba(0,0,0,0.06)` | свечение, фокус |
| `--danger` | `#C9675F` | `#A1453E` | ошибки (приглушённый) |

Цвета партий — не яркие, а оттенки серого с разной фактурой и подписью (чтобы различать без цвета):
- Мелодия — белый, сплошная линия.
- Бас — серый 60 %, толстая линия.
- Ритм — серый 40 %, пунктир.
- Фон — серый 25 %, точечный.
- Перкуссия — контурный.

## 2.3. Типографика (Google Fonts)
- **Заголовки**: `Cormorant Garamond` (500–600), крупно, плотный трекинг. Даёт «кино» и элегантность.
- **Интерфейс**: `Inter` (400–600).
- **Табы, тайминги, BPM, аккорды**: `JetBrains Mono`.
- Шкала: 12 / 14 / 16 / 20 / 28 / 44 / 72 px. Заголовок главной — 72 px на десктопе, 44 px на телефоне.

## 2.4. Фактура и движение
- Плёночное зерно: лёгкий SVG-шум поверх всего, opacity 0.04–0.06.
- Виньетка по краям главного экрана.
- Анимации медленные и мягкие: 250–400 мс, easing `cubic-bezier(0.2, 0.8, 0.2, 1)`. Появление — fade + сдвиг на 8 px.
- Визуализация звука: тонкая белая волна, дышит в такт при воспроизведении.
- Учитывать `prefers-reduced-motion`.

## 2.5. Экраны

**1. Главная / загрузка**
- Полноэкранный тёмный фон с зерном, крупный заголовок с серифом («Разложи песню на гитары»), под ним — зона drag & drop с тонкой пунктирной рамкой, которая «светится» при наведении файла.
- Ниже — «Недавние разборы»: горизонтальный ряд карточек.

**2. Обработка**
- По центру — волна песни, по которой бежит свет.
- Список этапов с галочками: «Разделяем на инструменты → Слушаем ритм → Ищем аккорды → Записываем мелодию → Собираем партии». Текущий этап пульсирует.
- Можно уйти — прогресс сохранится.

**3. Студия (главный экран)**
- Слева — панель состава: карточки игроков (имя, гитара, роль, сложность). Роли перетаскиваются между игроками.
- Сверху — инфо-бар: тональность, BPM, каподастр, строй, кнопки транспонирования и темпа.
- Центр — табы (alphaTab), переключатель «Моя партия / Партитура / Аккорды».
- Снизу — плеер, закреплённый у края: play, таймлайн с тактами и петлёй A–B, метроном, микшер (mute/solo/громкость для каждой партии).
- Пустые состояния и подсказки — короткие, в одном тоне.

**4. Экспорт**
- Модалка: выбрать игрока или всех, формат, кнопка «Скачать».

**5. Библиотека**
- Сетка карточек с генеративными обложками (абстрактная чёрно-белая волна песни), сортировка по дате.

## 2.6. Принципы UX
- **Сразу к музыке**: от загрузки до первой ноты — минимум шагов, разумные пресеты по умолчанию («Трио»).
- **Мгновенная реакция**: смена сложности или тональности не перезапускает анализ.
- **Честность**: рядом с автотранскрипцией — пометка «черновик, можно поправить» и кнопка правки.
- **Ошибки по-человечески**: «Не удалось выделить вокал — попробуй файл лучшего качества», а не стектрейс.
- **Клавиатура**: пробел, стрелки, L для петли, M — mute текущей партии.

Ты — senior full-stack разработчик и аудио-ML инженер. Мы строим веб-приложение «Fretlines» — гитарный аранжировщик для ансамбля. Полное ТЗ и дизайн-система лежат в файле SPEC.md в корне проекта: сначала прочитай его целиком и строго следуй ему.

## Что строим
Приложение принимает аудиофайл пользователя, разделяет его на стемы, транскрибирует мелодию вокала, бас, аккорды, фон и ритм и раскладывает всё на гитарные партии для 1–4 игроков с уровнями сложности. Результат — табы для каждого игрока (alphaTab), общая партитура и плеер с mute/solo.

## Стек
- Frontend: React + TypeScript + Vite, Tailwind CSS, Zustand, alphaTab, Framer Motion.
- Backend: Python 3.11, FastAPI, RQ + Redis для фоновых задач, SQLite (через SQLAlchemy, чтобы потом перейти на PostgreSQL).

- Запуск: docker-compose (frontend, backend, worker, redis). GPU опционально (флаг в .env), без GPU всё должно работать на CPU.
